# 🤖 Telegram Бот Контроля Обходов

Профессиональный бот для Telegram для автоматизации расписания обходов, фиксации выходов дежурных, контроля времени реакции и формирования ежедневных отчетов для руководства.

---

## 🌟 Ключевые возможности

* ⏰ **Автоматическое расписание обходов:**
  * Часовой пояс: `Asia/Tashkent` (`UTC+5`).
  * Рабочие дни: Понедельник — Суббота (`Пн–Сб`).
  * 12 точек контроля в день (утренние и послеобеденные обходы).
* 🔘 **Простое и чистое подтверждение:**
  * Лаконичное напоминание в чате: `🔔 10:00 — Время обхода!`.
  * Кнопка: `[ ✅ Я на обходе ]`.
  * После нажатия сообщение фиксирует факт: `✅ 10:00 — Обход выполнил @username в 10:02`, а кнопка автоматически убирается, сохраняя чат чистым.
* 🚨 **Контроль забывчивости (15 минут):**
  * Если в течение 15 минут никто не подтвердил выход на обход, бот отправляет тревогу в группу и личное уведомление руководству в ЛС.
* 👮‍♂️ **График смен и дежурств:**
  * Назначение дежурных через команду `/duty` или через панель управления.
  * Умное тегирование: бот зовет только тех, кто сегодня на смене.
* 📊 **Ежедневный отчет:**
  * Автоматическая отправка сводки 2 раза в день: промежуточная в 13:00 (обед) — администраторам в личку, итоговая в 18:45 — в группу и администраторам.
  * Время задаётся списком `daily_report_times` в `config.json`; последний отчёт дня — итоговый.
  * Выгрузка по требованию через `/report` или кнопку в меню.
* 📢 **Объявления и Опросы:**
  * Создание форматированных объявлений (с фото и закреплением) и опросов прямо из админ-панели.
* 🎛 **Интерактивная админ-панель:**
  * Управление расписанием (`ВКЛ` / `ВЫКЛ`), списком сотрудников и дежурствами через удобные кнопки.

## 🚀 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd <ИМЯ_ПАПКИ>
```

### 2. Настройка переменных окружения
Создайте файл `.env` на основе шаблона `.env.example`:
```bash
cp .env.example .env
```
Укажите ваш токен бота:
```env
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
```

### 3. Назначение администратора
Впишите свой Telegram ID в `admin_ids` в `config.json` (узнать ID можно, например, у @userinfobot).
Админы задаются только вручную: без этого админ-панель, `/setchat` и `/test` никому не доступны.
Если ID неизвестен, впишите ник в `admin_usernames` (например, `["bekaotegenov"]`): когда этот человек
впервые напишет боту, бот сам перенесёт его в `admin_ids` по Telegram ID и уберёт ник из списка.

Полезные настройки в `config.json`:
* `advance_minutes` — за сколько минут до обхода присылать напоминание (по умолчанию 5).
* `escalation_minutes` — через сколько минут без подтверждения поднимать тревогу.
* `keep_days` — сколько дней хранить историю в `bot_data.json` (0 — не удалять).
* `group_autodelete_seconds` — через сколько секунд удалять в группе команды (`/duty`, `/report`, `/status`…) и ответы бота на них (по умолчанию 120, 0 — не удалять).
  Чтобы бот мог удалять сообщения участников, сделайте его администратором группы с правом «Удаление сообщений».

Смены и дежурные:
* День делится на две смены: 🌅 утро и 🌇 после обеда. Граница — `shift_split` в `config.json` (по умолчанию `13:30`).
* `/admin` → «👮‍♂️ Дежурные на сегодня» → «📅 График на неделю»: на каждый день недели назначаются люди
  на утро и на после обеда. График повторяется каждую неделю (`weekly_duty` в `config.json`).
* На конкретный день можно сделать замену: «🌅 Изменить утро» / «🌇 Изменить после обеда» на экране «сегодня».
  Замена действует только в этот день, «↩️ Вернуть сегодня по графику» её убирает.
* Напоминание отмечает дежурных своей смены; если на смену никто не назначен — всех сотрудников.
* В «⏰ График обходов» обходы сгруппированы по сменам, в заголовке смены — сколько людей сегодня на смене.
* `/duty`, статус и отчёт показывают дежурных по сменам и общее число людей.

Надёжность:
* Одновременно может работать только одна копия бота (замок `bot.lock`): повторный запуск, например `run.bat` при работающей автозагрузке, сразу завершится, чтобы напоминания не дублировались.
* Лог пишется в `bot.log` рядом с данными (до 4 файлов по 1 МБ) — пригодится при фоновом запуске.
* При сбое связи с Telegram отправка повторяется до 3 раз; задачи, запуск которых задержался (сон ПК), выполняются в течение 5 минут.

Отчёт:
* 🟢 вовремя, 🟠 подтверждён после тревоги (с опозданием), 🔴 пропущен, 🟡 ожидает, ⚫ не отправлен (бот был выключен или группа не привязана).
* Тестовые обходы в отчёт не попадают, срочные вызовы показываются отдельным списком и не влияют на процент.
* `/report`, `/status` и `/duty` доступны в рабочей группе и администраторам; посторонним в личке бот отказывает.

Тихий режим в группе:
* Тревога «обход не подтверждён» не пишется новым сообщением, а превращает само напоминание в тревогу (кнопка остаётся). Руководство получает тревогу в личку.
* Промежуточный отчёт (13:00) приходит только администраторам в личку, в группу — только итоговый.
* Отчёты отправляются без звука.

### 4. Установка зависимостей и запуск

#### На Windows:
Просто запустите файл:
```cmd
run.bat
```

#### Вручную через терминал:
```bash
python -m venv .venv
source .venv/bin/activate  # На Windows: .venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```

#### Через Docker:
```bash
docker build -t telegram-obhod-bot .
docker run -d --restart=always --name obhod-bot --env-file .env -v obhod-data:/data telegram-obhod-bot
```
`.env` не попадает в образ, токен передаётся через `--env-file`. Настройки и история хранятся в томе `/data`:
при первом запуске туда копируется `config.json` из образа, дальше бот работает с копией в томе.

#### VPS 24/7 (рекомендуется):
Подойдёт самый дешёвый VPS с Ubuntu 22.04/24.04 или Debian 12 в Европе (Германия, Финляндия, Нидерланды) —
боту хватает 512 МБ памяти.

1. Отправьте свежий код на GitHub (`git push origin main`) — сервер скачивает его оттуда.
2. Подключитесь к серверу: `ssh root@IP_СЕРВЕРА`.
3. Скачайте и запустите установщик (он спросит токен бота):
   ```bash
   curl -fsSL https://raw.githubusercontent.com/madsaomi/obhodbot/main/deploy/install.sh -o install.sh
   sudo bash install.sh
   ```
4. Проверьте привязку группы. При каждом запуске бот сам проверяет настройку и пишет итог в лог
   и администраторам в личку: привязана ли группа, состоит ли в ней бот, есть ли права админа
   и удаления сообщений. Если группа не привязана — напишите `/setchat` в рабочей группе;
   после этого бот пришлёт в личку результат проверки. Повторить проверку в любой момент: `/check`.
5. Остановите бота на своём компьютере и уберите его из автозагрузки (`remove_from_startup.bat`) —
   иначе две копии будут мешать друг другу.

Данные бота лежат на сервере в `/opt/obhodbot/data` (`config.json`, `bot_data.json`, `bot.log`).
При первом запуске туда копируется `config.json` из репозитория. Чтобы перенести историю обходов
с компьютера: `scp bot_data.json root@IP_СЕРВЕРА:/opt/obhodbot/data/`, затем `docker compose restart` в `/opt/obhodbot`.

Полезные команды (в папке `/opt/obhodbot`):
* `docker compose logs -f bot` — лог в реальном времени
* `docker compose restart` — перезапуск (например, после правки `data/config.json`)
* `sudo bash deploy/install.sh` — обновить бота до последней версии с GitHub

#### Amvera:
Бот автоматически использует постоянное хранилище `/data` (`persistenceMount` в `amvera.yml`),
поэтому настройки и история переживают передеплой. Токен задайте переменной окружения `BOT_TOKEN`.

## 💬 Команды бота

### В личных сообщениях:
* `/start` — Запуск и открытие меню быстрого доступа
* `/admin` — Открытие интерактивной панели управления
* `/report` — Показать итоговый отчет за сегодня
* `/duty` — Проверить, кто дежурит на смене

### В рабочей группе:
* `/setchat` — Привязать текущую группу к боту
* `/duty` — Посмотреть дежурных или заступить на смену
* `/report` — Отчет по обходам за текущий день
* `/status` — Проверить статус системы и точное время
* `/test` — Отправить тестовый вызов на обход
